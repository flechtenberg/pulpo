   .. py:method:: instantiate(choices=None, demand=None, upper_limit=None, lower_limit=None, upper_elem_limit=None, upper_imp_limit=None, lower_elem_limit=None, lower_imp_limit=None, dependent_constraints=None, default_limits=None, imp_goals=None, objective='weighted_sum', scale=False)

      Combines inputs and instantiates the optimization model.

      :param choices: Choices for the model: ``{label: {activity: capacity}}``, or a list of
                      activities when none has a capacity. A capacity of ``float('inf')``
                      or ``None`` means no limit; avoid huge finite stand-ins such as
                      ``1e10``. ``None`` means "no limit" in the limit dicts below too;
                      ``default_limits`` takes numbers.
      :type choices: dict
      :param demand: Demand data.
      :type demand: dict
      :param upper_limit: Upper limit constraints. On a choice alternative it replaces the
                          capacity, with a warning.
      :type upper_limit: dict
      :param lower_limit: Lower limit constraints. Equal lower and upper limits on a process
                          fix its output as a supply (its product's balance gets a slack);
                          equal limits of 0 switch the process off.
      :type lower_limit: dict
      :param upper_elem_limit: Upper elemental limit constraints.
      :type upper_elem_limit: dict
      :param upper_imp_limit: Upper impact limit constraints.
      :type upper_imp_limit: dict
      :param lower_elem_limit: Lower elemental limit constraints.
      :type lower_elem_limit: dict
      :param lower_imp_limit: Lower impact limit constraints.
      :type lower_imp_limit: dict
      :param dependent_constraints: Dependent constraints between scaling vectors.
                                    Format: {constraint_name: {'left': {activity: weight}, 'right': {activity: weight}}}
      :type dependent_constraints: dict
      :param default_limits: Custom default limits. If None, uses standard values.
                             Required keys: 'lower_bound', 'upper_bound', 'upper_inv_bound',
                             'lower_inv_bound', 'lower_imp_bound', 'upper_imp_bound'.
                             Categories listed in imp_goals ignore 'lower_imp_bound'/
                             'upper_imp_bound' (the goal is a soft limit, not a hard Var
                             bound) unless also given an explicit upper_imp_limit/
                             lower_imp_limit. Finite 'lower_bound' / 'upper_bound'
                             put a bound on every activity, which has no physical
                             meaning and makes solve(formulation='reduced') build the
                             whole of S; they raise a FutureWarning. Set
                             lower_limit / upper_limit on the processes that have
                             a real limit instead. default_limits may be
                             deprecated in a near-future release.
      :type default_limits: dict, optional
      :param imp_goals: Goal-programming soft limits {method_string: limit}. Unlike
                        upper_imp_limit these CAN be transgressed; used with
                        objective='goal'. Categories with a goal are kept in the
                        model even if their objective weight is 0.
      :type imp_goals: dict, optional
      :param objective: 'weighted_sum' (default) or 'goal'. With 'goal' the model
                        minimizes the average transgression level
                        (1/K) * sum_h max(0, impact_h / imp_goals_h - 1) over the K
                        categories in imp_goals (weights are ignored).
      :type objective: str, optional
      :param scale: Equilibrate the LP before it is handed to the solver
                    (default False; see :mod:`pulpo.utils.scaling`). On an
                    ecoinvent-scale technosphere (coefficients 1e-13 .. 1e11)
                    the unscaled LP is solved to the solver's tolerance
                    *relative to the largest coefficient of each row*, which
                    lets facility-scale products be under-supplied for free
                    and moves the optimum by ~1%. The solution is reported in
                    original units either way.
      :type scale: bool, optional


   .. py:method:: solve(GAMS_PATH=False, solver_name=None, options=None, neos_email=None, formulation='full')

      Solves the optimization model and calculates additional methods and inventory flows if needed.

      :param GAMS_PATH: Solve with the GAMS installation in this
                        directory (``True``: the directory in the ``GAMS_PULPO`` environment
                        variable), using ``solver_name`` as the GAMS solver (default CPLEX).
      :type GAMS_PATH: str or bool, optional
      :param solver_name: 'highs' (default) or 'gurobi'; with formulation='full'
                          also any GAMS or NEOS solver.
      :type solver_name: str, optional
      :param options: Solver options: option names and values for HiGHS
                      and Gurobi (an unknown HiGHS option or an invalid value raises a
                      ValueError), a list of option lines for GAMS. NEOS does not use them.
      :type options: dict, optional
      :param neos_email: The e-mail address NEOS requires when ``solver_name``
                         names a NEOS solver (formulation='full'); without it, the ``NEOS_EMAIL``
                         environment variable is used.
      :type neos_email: str, optional
      :param formulation: 'full' (default) solves the Pyomo LP over every process;
                          'reduced' solves the same problem over the alternatives only
                          (see :mod:`pulpo.utils.reduced`).
      :type formulation: str, optional

      :returns: Results of the optimization (a :class:`pulpo.utils.reduced.ReducedResults`
                with formulation='reduced').
      :rtype: results

      :raises pulpo.utils.optimizer.SolveError: the solve did not end optimal (infeasible,
          unbounded, or stopped by a time or iteration limit). Nothing is loaded:
          the instance keeps its previous values. With formulation='reduced' it is
          the subclass :class:`pulpo.utils.reduced.ReducedSolveError`.

   .. py:method:: retrieve_envflows(keys=None, activities=None, categories=None)

      Retrieves environmental flows from the database based on given filters.

      Filters are matched exactly and combined with AND; ``keys`` takes precedence.
      Each filter takes one value or a list of them. Categories are tuples such as
      ``('air', 'urban air close to ground')``.

      :param keys: Flow keys, as (database, code) tuples or their string form.
      :type keys: optional
      :param activities: Flow names.
      :type activities: optional
      :param categories: Flow categories, as tuples or their string form.
      :type categories: optional

      :returns: The matching flows; empty, with a warning, if none match.
      :rtype: list


   .. py:method:: retrieve_methods(string='')

      Retrieves methods from the database based on a search string.

      :param string: Search string for methods.
      :type string: str

      :returns: List of methods that match the search string.
      :rtype: methods

   .. py:method:: summarize_results(zeroes=False)

      Summarizes the results of the optimization.


   .. py:method:: extract_results(extractparams: bool = False)

      The results of the last solve, as DataFrames keyed by the sheet names of
      :meth:`save_results`.

      The keys are 'Scaling Vector', 'Intervention Vector', 'Slack', 'Impacts',
      'Transgressions', 'Demand', 'Choices' (a dict with one DataFrame per choice),
      'Constraints Upper', 'Constraints Lower' and 'Constraints Upper Elem'.

      :param extractparams: Also return the instance's parameters.
      :type extractparams: bool, optional

      :returns: The results, as described above.
      :rtype: dict
